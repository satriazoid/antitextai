# Using antitextai from another agent or AI code tool

The point of this repository is that you clone it once and every agent you use can act on the
same rules. There are two ways that happens: the tool runs as a command (works everywhere), and
the skill file teaches an agent the judgment rules (works wherever the agent reads a skill or an
instruction file).

## The short version

```bash
git clone https://github.com/satriazoid/antitextai.git
cd antitextai
python -m antitextai scan .            # works immediately, nothing to install
```

Then pick one of:

```bash
# A. Let an installer copy SKILL.md where your tool looks.
bash scripts/install.sh --target claude-code,opencode,cursor,copilot,codex,gemini,windsurf,cline,aider,hermes,omp
pwsh scripts/install.ps1 -Target claude-code,opencode,cursor,copilot,codex,gemini,windsurf,cline,aider,hermes,omp

# B. Do it by hand for one tool. Claude Code, global:
mkdir -p ~/.claude/skills/antitextai && cp SKILL.md ~/.claude/skills/antitextai/

# C. Skip the agents entirely and gate it in CI or a hook (see the bottom of this file).
```

## What an agent must know

Four facts cover almost everything. They are the first four lines of `SKILL.md` too.

1. **Use the CLI, do not hand-edit.** `python -m antitextai clean --write PATH` applies the
   deterministic half exactly, and `verify PATH --strict` proves it afterwards.
2. **Em dash (`—`) and en dash (`–`) are never auto-replaced.** A numeric range, a compound noun,
   and a clause break each need a different replacement. The agent reports them, decides each one,
   and runs `verify --allow-dashes` only after reviewing them.
3. **Code safety first.** `x = "# end of loop"`, `url = 'http://x--y/z'`, and test fixtures where
   the character is the data under test are never touched. The scan classifies `keep` characters
   (accented Latin, Greek, CJK, math symbols) and leaves them alone.
4. **Prove it, do not assert it.** `verify --strict` exits 1 while anything is still dirty. An
   agent that reports success without running it is guessing.

## Skill-aware tools (Agent Skills standard)

These read a folder containing `SKILL.md` with `name` and `description` frontmatter. Clone the
repo, copy the skill folder, done. `SKILL.md` references the package at the repo root, so keep
the clone around (or `pipx install` the CLI and let the skill call `antitextai`).

| Tool | Project path | Global path |
| --- | --- | --- |
| Claude Code | `.claude/skills/antitextai/SKILL.md` | `~/.claude/skills/antitextai/SKILL.md` |
| opencode | `.opencode/skills/antitextai/SKILL.md` | `~/.config/opencode/skills/antitextai/SKILL.md` |
| Any reader of the `.agents` convention | `.agents/skills/antitextai/SKILL.md` | `~/.agents/skills/antitextai/SKILL.md` |
| Hermes Agent | `./skills/antitextai/SKILL.md` | `~/.hermes/skills/antitextai/SKILL.md` (`%LOCALAPPDATA%\hermes\skills\` on Windows) |
| omp (oh-my-pi) | `.omp/skills/antitextai/SKILL.md` | same under the omp config directory |

opencode additionally discovers `.claude/skills/` and `.agents/skills/`, so one copy can serve
several tools. Claude Code merges custom commands into skills, which means `/antitextai` works as
an invocation once the folder is in place.

## Instruction-file tools

These read a markdown instruction file rather than a skill. `integrations/` holds a ready version
for each, and `AGENTS.md` content is generated by the installer if your tool wants one.

| Tool | File | Notes |
| --- | --- | --- |
| Codex CLI and other AGENTS.md readers | `AGENTS.md` | Project root wins; `~/.codex/AGENTS.md` is the global equivalent. |
| GitHub Copilot | `.github/copilot-instructions.md` | Repository-wide. Path-scoped variants go in `.github/instructions/*.instructions.md`. Copilot also reads `AGENTS.md`. |
| Cursor | `.cursor/rules/antitextai.mdc` | `.mdc` extension is required; the frontmatter in our file scopes it by description and globs. Cursor also reads `AGENTS.md`. |
| Windsurf | `.windsurf/rules/antitextai.md` | Project rules directory. |
| Cline | `.clinerules/antitextai.md` | Directory form, so it can grow later. |
| Aider | `CONVENTIONS.md` | Reference it from `.aider.conf.yml` with `read: CONVENTIONS.md`. |
| Gemini CLI | `GEMINI.md` | Project root. `~/.gemini/GEMINI.md` is the global equivalent. |

Anything not on this list still works if it can run a shell command or read a file you point it
at. The generic recipe:

1. Give the agent this sentence:
   *"Before reporting any text or code cleanup as done, run `python -m antitextai verify PATH --strict`
   and paste the output. Read `SKILL.md` for the rules."*
2. Put the file at the path that tool reads for project instructions.
3. Keep the clone, or `pipx install "git+https://github.com/satriazoid/antitextai"` so the
   `antitextai` command exists outside the repo.
4. Verify once by hand that the agent actually ran the tool. A self-report is not proof; the
   `verify` output is.

## Prompt to paste into an agent

```text
Clean the AI tells out of <FILES OR DIRECTORY>.

1. Run: python -m antitextai scan <TARGET>       (inventory first, it changes nothing)
2. Run: python -m antitextai clean --write <TARGET>
3. Read the diff. Every touched line must still say the same thing. Never edit inside string
   literals, fixtures, or i18n data.
4. Handle the judgment rules yourself: em and en dashes, docstrings, banners that mark a real
   module boundary, WHAT-comments, over-long identifiers, hedging stacks.
5. Run: python -m antitextai verify <TARGET> --strict     (must exit 0)
6. Report the verify output verbatim, plus the list of dashes you decided by hand.
```

## CI and hooks

GitHub Actions step:

```yaml
- uses: actions/setup-python@v5
  with:
    python-version: "3.12"
- name: No AI tells
  run: |
    python -m antitextai verify . --strict \
      --exclude "examples/**" --exclude "tests/**"
```

`examples/demo_before.md` is a deliberately dirty fixture, so exclude `examples/` or the check
will (correctly) fail on it. Keep `--allow-dashes` only when the dashes were reviewed by hand.

pre-commit, via the bundled hook definition:

```yaml
# .pre-commit-config.yaml
repos:
  - repo: https://github.com/satriazoid/antitextai
    rev: v1.0.0
    hooks:
      - id: antitextai
```

The hook runs `antitextai clean --write --quiet`, so a commit that introduced tells is rewritten
and rejected, which is what you want: the cleaned version is staged on the next attempt.

A plain git hook works too, if you would rather not add a framework:

```bash
# .git/hooks/pre-commit
#!/bin/sh
antitextai clean --write --quiet $(git diff --cached --name-only --diff-filter=ACM) || exit 1
git add -u
```

## Keeping the skill alive in an agent's workflow

Skills are only useful if the agent loads them at the right moment. Trigger phrases that work
with the description in `SKILL.md`:

- "this file has Claude fingerprints in it"
- "clean the AI tells out of this"
- "remove the zero-width characters"
- "de-AI this document"
- "why does this file have hidden characters"

If your tool supports always-on rules (Cursor `alwaysApply: true`, a pre-commit hook, a CI gate),
prefer the gate. The mechanical half should not depend on an agent remembering to ask.
