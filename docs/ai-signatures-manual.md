# Comprehensive Manual of AI Text & Code Signatures

This document provides an exhaustive, machine-readable reference of invisible characters, non-standard typography, comment patterns, and structural formats commonly generated by Large Language Models (LLMs). It serves as the specification for cleaning scripts, anti-AI text filters, and code refactoring rules.

---

## 1. Invisible & Special Unicode Characters

LLMs frequently output non-standard or invisible Unicode characters as artifacts from training datasets, system prompt wrappers, tokenization edge cases, or platform copy-pasting.

| Character Name | Unicode Hex / Representation | Common AI Usage / Origin | Action Required |
| :--- | :--- | :--- | :--- |
| **Zero-Width Space** | `\u200B` | System prompts, watermark tokens, boundary markers. | Delete (`""`) |
| **Zero-Width Non-Joiner** | `\u200C` | Ligature suppression artifacts during decoding. | Delete (`""`) |
| **Zero-Width Joiner** | `\u200D` | Compound character/emoji joining artifacts. | Delete (`""`) |
| **Byte Order Mark (BOM)**| `\uFEFF` | API output string prefixes. | Delete (`""`) |
| **Non-Breaking Space** | `\u00A0` | Lists, tables, and code indentations copied from AI UIs. | Convert to Standard Space (`\u0020`) |
| **Em-Dash** | `\u2014` (`—`) | Heavy usage in clauses without spaces (`word—word`). | Replace with `,`, `:`, or `-` |
| **En-Dash** | `\u2013` (`–`) | Misused for ranges, lists, or clauses. | Replace with `-` or context word |
| **Smart Double Quotes** | `\u201C`, `\u201D` (`“`, `”`) | Default AI typographic rendering. | Convert to Straight Quote (`"`) |
| **Smart Single Quotes** | `\u2018`, `\u2019` (`‘`, `’`) | Default AI typographic rendering / apostrophes. | Convert to Straight Quote (`'`) |
| **Horizontal Ellipsis** | `\u2026` (`…`) | Single-character ellipsis token. | Convert to three dots (`...`) |

## 2. Source Code Signatures & Over-Commenting Patterns

AI code generation is characterized by redundant explanations, rigid boilerplate, and over-descriptive naming conventions.

### 2.1 Code Commenting Fluff
- **Self-Explanatory Syntax Comments:** Comments explaining fundamental language operations rather than logic.
  - *AI Pattern:*
    ```python
    # Increment counter by 1
    counter += 1
    # Initialize an empty list
    results = []
    ```
  - *Rule:* Delete all comments that describe *WHAT* syntax does instead of *WHY* logic exists.

- **Block & Scope End Markers:** Redundant comments marking the end of control structures or functions.
  - *AI Pattern:* `# end of loop`, `// end function handleRequest`, `/* end class Controller */`.
  - *Rule:* Delete all end-of-block comment flags.

- **Visual Section Separators:** Excessive ascii-art boundaries dividing functions.
  - *AI Pattern:*
    ```python
    # ==========================================
    # HELPER FUNCTIONS
    # ==========================================
    ```
  - *Rule:* Delete decorative separator lines. Maintain clean 1–2 blank lines between functions.

- **Boilerplate Docstrings:** Overly verbose JSDoc/Docstrings for trivial functions.
  - *AI Pattern:*
    ```python
    def add(a, b):
        """
        Adds two integers.
        
        Parameters:
        a (int): First number.
        b (int): Second number.
        
        Returns:
        int: The sum of a and b.
        """
        return a + b
    ```
  - *Rule:* Strip redundant docstrings on internal, utility, or self-explanatory functions.

### 2.2 Naming and Indentation Issues
- **Hyper-Descriptive / Generic Identifiers:** Variable names that over-explain role (`processed_user_data_response_object`).
  - *Rule:* Refactor to concise, context-aware names (`data`, `user_res`, `res`).
- **Mixed Indentation via NBSP:** Presence of `\u00A0` within tabs/spaces causing execution errors (e.g., Python `IndentationError`).
  - *Rule:* Enforce strict ASCII spaces (`\u0020`) or standard tab characters across all code blocks.

## 3. Markdown & Structural Text Signatures

Written content generated by LLMs adheres to predictable framing, list structures, and phrasing patterns.

### 3.1 List & Typography Patterns
- **Bold Keyword Prefixes:** Pervasive use of bold key terms at the start of every list item.
  - *AI Pattern:*
    - `* **Optimization:** Implement caching mechanisms...`
    - `* **Security:** Enforce strict CORS policies...`
  - *Rule:* Remove forced leading bold terms or convert into standard narrative paragraphs.

- **Excessive Subheading Fragmentation:** Splitting short explanations into numerous subheaders (`###`).
  - *Rule:* Merge fragmented single-sentence paragraphs under unified headings.

### 3.2 Conversational Wrappers (The "Sandwich" Pattern)
- **Introductory Conversational Fluff:**
  - *Phrases:* *"Certainly! Here is...", "Sure thing! Below is...", "In today's fast-paced digital landscape..."*
  - *Rule:* Strip the entire opening conversational line/paragraph before the main content.

- **Outro Summary Fluff:**
  - *Phrases:* *"In conclusion...", "Overall, by implementing these steps...", "Hope this helps!"*
  - *Rule:* Delete the conclusion paragraph if it merely restates the obvious points.

- **Pre-Code Block Meta-Text:**
  - *Phrases:* *"Here is the complete Python script to achieve this:"*
  - *Rule:* Delete introductory meta-text preceding standard Markdown code blocks (` ``` `).

## 4. Master Regular Expression (Regex) Ruleset

This table provides standard regex patterns for implementing automated cleanup tools.

| Rule Category | Regex Pattern | Replacement |
| :--- | :--- | :--- |
| **Invisible Characters** | `[\u200B\u200C\u200D\uFEFF]` | `""` (Empty string) |
| **Non-Breaking Space** | `\u00A0` | `\u0020` (ASCII Space) |
| **Dashes (Em/En)** | `[\u2013\u2014]` | `-` or `,` |
| **Smart Double Quotes** | `[\u201C\u201D]` | `"` |
| **Smart Single Quotes** | `[\u2018\u2019]` | `'` |
| **Ellipsis Token** | `\u2026` | `...` |
| **AI Intro Fluff** | `(?i)^(certainly\|sure,!\s*here\|in today's).*$` | Delete Line |
| **AI Outro Fluff** | `(?i)^(in conclusion\|overall,?\s*by\|hope this helps).*$` | Delete Line |
| **End Block Comments** | `(?i)(//\|#)\s*end\s+(of\s+)?(block\|loop\|function\|class).*$` | Delete Line |
| **Visual Separators** | `^[\s/#*]*[=\-\*]{5,}[\s/#*]*$` | Delete Line |
